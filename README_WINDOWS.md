# 合拍 DUET — Windows 版

Windows Chrome／Edge 的雙影片工作台。影片在瀏覽器本機處理；不會上傳使用者影片。

## 基準

從 iPhone 第 17 版的 `restore-20260910-important` 建立，原始 commit：
`e52f852488423422d55315aef0a93b6dbe92f297`。

本專案使用獨立目錄、Git 與 Sites 發布目標；iPhone 專案與還原標籤保留。
歷史 iPhone 開發記錄見 README.md，移植背景見 HANDOFF_WINDOWS.md。

## Windows 操作

- 點選 A／B 或各自拖入一支影片，再按「用音訊自動對齊」。
- 對齊後拖曳構圖，方向鍵移動 1 個輸出像素，Shift＋方向鍵移動 10 個像素。
- 各自裁切、調寬高、圖層或使用並排／子母畫面配置。
- 雙影片試聽有自己的時間差，使用共用音訊時鐘，不修改主編輯與成品。
- 融合後以「下載影片」儲存。依瀏覽器實際能力輸出 MP4 或 WebM。

目前保留每部 3～180 秒、250 MB，1080p／720p／480p、目標 30 fps 的輸出選項。
1080p 橫式為 1920×1080、直式為 1080×1920、方形為 1080×1080，目標影像位元率為 8 Mbps。
輸出採原速即時錄製，請保持分頁在前景，避免睡眠。

## 開發

Node 24，沿用 package-lock.json：

```powershell
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
npm run typecheck
npm test
npm run build
npm run test:build
```

測試需要 FFmpeg。Vite 已忽略 `.tmp` 與本機 `att.*` 素材，避免 Windows 檔案鎖使開發伺服器中斷。
本機測試影片、驗證報告與輸出不進 Git，也不放入 public。

## 驗證記錄（2026-09-10）

- 88 項自動測試通過：對齊、裁切、音訊備援、取消、共用時鐘、重複輸出及鍵盤微調。
- 正式 Worker 路徑、六種確認長度、靜音邊界回歸、MOV PCM 解碼與 AAC 不支援時備援通過。
- 兩支使用者 MP4：1280×720、H.264／AAC、44.1 kHz，約 34.73／35.02 秒。
- 全段比對的自動與 2～5 秒選項確認 +1.86 秒；交換來源為 -1.86 秒。
  1 秒選項信心不足，維持待確認，不硬判成功。
- Edge 實機瀏覽器自動驗收：匯入、快速音訊解碼、對齊、裁切狀態、方向鍵、試聽獨立、兩次 MP4 輸出通過。
- 已下載的 Edge MP4 有 H.264 影像與 AAC 音訊、1280×720、35.04 秒。
  成品第 34 秒：A 區域為黑幕、B 持續顯示；第 33.5～34.5 秒的 A 音軌為靜音。
- 瀏覽器驗收以 Windows 上的無頭瀏覽器自動化執行，不代表所有 MOV／HEVC／HDR 格式皆經驗證。
- Chrome 實際瀏覽器自動驗收也通過：拖放匯入、+1.86 秒對齊、獨立試聽、裁切、窄視窗與兩次 MP4 輸出。

- 1080p 實際輸出驗證：Edge 1920×1080（完整使用者影片約 35.02 秒）、Chrome 1080×1920 與 1080×1080 都含 H.264 影像和 AAC 聲音。
  瀏覽器即時錄製使用可變幀率；此次無頭測試約 23～27 fps，30 fps 為目標而非固定幀率保證。
