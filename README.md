# 合拍 DUET

以 iPhone Safari 為主要使用環境的雙影片融合編輯器。檔案、音訊分析與編碼均留在瀏覽器，不上傳使用者影片。

## 使用

1. 選取兩段播放同一版本音樂的影片，或按「載入測試影片」。
2. 按「用音訊自動對齊」。可選自動、1、2、3、4、5 秒，預設自動：找到明確音訊對齊點即成功；1 至 5 秒為指定比對長度。全段音樂先找時間差，局部片段明確 match 即算成功，後段不需一致；較短影片使用可用的重疊片段。不確定的結果需要人工確認，也可手動指定時間差。
3. 拖曳任一影片，拉右下角改變大小；使用水平位置、垂直位置、寬度、高度欄位精準配置。可解開比例鎖，調整前後層級，選擇橫式、直式或方形畫布。
4. 融合，預覽，透過系統分享或下載保存。iPhone 使用 HTTPS 網站，在分享選單選「儲存影片」；網站不能直接寫入照片圖庫，也無法確認使用者是否完成儲存。

## 時間軸定義

offset > 0 表示 A 的歌曲段落需前進 offset 秒才能與 B 對應，裁掉 A 開頭 offset 秒；offset < 0 則裁 B。這是音樂位置的差值，不是實際拍攝時間差；影片可以在不同時間、不同場景拍攝。**保留前端對齊後最長的尾段；較短影片播放結束後，其矩形區域持續畫成不透明黑色**，即使它在另一部影片上層也不透出下層。輸出聲音僅用使用者選擇的音軌，該音軌先結束時，其後靜音。

## 範圍與限制

- 初版每部 3 秒至 3 分鐘、250 MB 以下。長片或高解析度來源可能超過手機記憶體或解碼能力，失敗時需縮短或降解析度。
- 以 50 Hz 六頻帶音訊變化特徵與 FFT 互相關估計固定時間差；非時鐘飄移、變速錄影或多段剪輯校正。高度週期性聲音、嚴重失真、無音訊可能需要手動調整。
- 使用 Canvas + Web Audio + MediaRecorder 即時輸出，30 fps、長邊 1280（方形 720）。輸出約需影片長度的時間，需保持前景。融合前各定位一次，之後以原速播放，不做持續 seek 或播放速度校正。背景切換、逾時或編碼失敗時中止。
- 優先 MP4/H.264/AAC，依瀏覽器能力退回 WebM，副檔名保持正確。WebM 不保證能存入 iPhone 照片。
- 使用 MediaRecorder 的雙播放器輸出不保證逐幀精準或 HDR 色彩保真。真機 Safari 的 HEVC、HDR、長片、分享及編码行為仍需實測。
- 第一版不儲存專案；重新整理會清除所選來源和未下載輸出。

## 本機開發

Node 22.13+（測試直接執行 TypeScript 需較新的 Node；此工作環境使用 Node 24）。

```sh
npm install
npm run dev -- --host 0.0.0.0
npm run typecheck
npm test
npm run build
```

重建素材需 Python 及 PATH 上的 FFmpeg：`npm run demo:generate`。測試對齊使用 FFmpeg 解碼實際 AAC 音軌。素材 A 為 22 秒，素材 B 為 14 秒、晚開始 2.34 秒；兩者有獨立噪音。對齊後輸出 19.66 秒，B 最後 5.66 秒為黑幕。

## 驗證紀錄

- 10 個核心測試涵蓋含噪 AAC 素材、反向差值、相同音訊、靜音、無關音訊、完整尾段、無效差值、黑幕遮蓋、繪圖順序與 FFT 回轉。
- 型別檢查與正式編譯另執行確認。
- 尚未在實體 iPhone 操作，也未執行瀏覽器端端到端錄製驗證。
- WebMCP 僅提供 read_video_composition_status，透過 feature detection 註冊；此環境沒有支援的 WebMCP 驗證 context，未驗證該契約。

參考：

- https://webkit.org/blog/11353/mediarecorder-api/
- https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share

本次編輯器範圍（app、lib、tests、scripts）的 oxlint 與 TypeScript 檢查通過。完整 `npm run lint` 尚有產生器預載、未使用的 components/ui 與 hooks 的既有規則錯誤；保留原始範例檔案，未停用其檢查規則。

## 音訊分析修正

正式版 Worker URL 改為由瀏覽器網址解析，避免伺服器編譯把 import.meta.url 固定為 file:///ROOT 路徑。六頻帶特徵加上對稱 100 ms 平滑以抑制不同錄音環境的快速噪音變化；當時信心門檻維持不變；目前全段音樂比對與自動模式見下方說明。新增 Worker 生命週期測試，以及 npm run test:build 驗證正式輸出路徑和編譯後分析程式。使用者實拍影片僅在本機驗證，不納入 repo 或網站。

## 融合播放與進度修正

- 按下融合後立即開啟原生對話框，顯示裁切起點、準備階段、實際合成畫面與百分比；成功後在同一視窗預覽與下載，錯誤不再藏在頁面上方。
- 來源播放器置於可見視窗；選定影片透過 MediaElementAudioSourceNode 供應音軌、喇叭監聽音量為 0，另一部保持靜音；以 AudioContext 時鐘控制輸出，只在開始前依固定音樂秒差定位一次。融合中不再比較影片秒差、不跳轉、不調速，也不因播放秒差觸發錯誤。
- 保留前端裁切；音軌使用相同裁切起點，較短影片结束後黑幕，聲音結束後靜音。可選輸出標準 720p 或省電 480p；此設定降低合成與編碼負擔，不改變來源檔的解碼解析度。
- 每個播放、解碼、定位、封裝等待均有逾時與取消處理。測試涵蓋播放器落後時不再跳轉或調速、正負秒差只在開始前裁切一次、短片黑幕與輸出生命週期。這些模拟測試不等於 iPhone 真機編碼驗證。

- 合成畫面限制每秒最多 30 次繪製，進度約每 250 ms 更新；避免高更新率螢幕重複繪製增加手機負擔。

## 畫面裁切

對齊後選擇影片 A 或 B，展開「裁切影片的畫面」，拖動四邊或右下角調整保留範圍，框內拖曳移動範圍；上下左右滑桿也可獨立裁切。按「套用裁切」後再調整編排大小位置；「還原完整畫面」可取消該影片的裁切。兩部影片分別記錄來源矩形，編排縮圖與 Canvas 融合使用相同範圍，快速配置依裁切後比例排版。畫面裁切不改變音訊對齊秒差與片長，也不修改原始檔案。新增裁切邊界、預覽座標與成品繪圖回歸測試；尚未進行 iPhone 觸控實測。

裁切參考圖固定使用對齊後時間 0 的第一幀，與可拖動的時間軸縮圖分開保存。改變自動或手動對齊秒差時更新該參考圖；查看後續影格不會更换裁切參考圖。

## 音樂 match 判定

先以全段音訊的六頻帶特徵搜尋正負時間差，保留多個不同候選；全段平均分數僅用來找候選，不當作一票否決的門檻。依全段支持程度，從各候選的重疊區找清楚的局部片段，再將該片段與另一部完整錄音比對，確認時間差唯一且一致。拍手、說話、不同尾段可以降低部分片段的分數，但不會否決其他明確的音樂 match。

預設自動模式嘗試 0.3、0.6、1、2、3、4、5 秒的局部確認長度；1 至 5 秒指定確認片段長度，並非限制全段搜尋範圍。大量局部搜尋採較高的相似度要求，避免偶然的弱峰值。若全段候選沒有通過，仍保留前段明確 match 的退路，避免極長的不同尾段掩蓋短前段。

共同聲音不足、靜音或重複片段導致候選不明確時，不自動確認。這仍是固定時間差對齊，不是人聲分離，也不校正變速或時鐘漂移。回歸測試涵蓋開頭不同但中段相同、正負時間差、不同尾段、含噪 AAC、拍手與語音型音調干擾。

## 匯入與音訊診斷

自動與 1 至 5 秒以單選按鈕列顯示於影片匯入區上方，初始即可看見；預設自動。音訊分析與輸出現已改用 nivitrack iPhone 版的播放器路徑，詳見下節。

## iPhone 播放器音訊路徑

匯入只以原生 video 元素讀取影片與縮圖；分析和輸出均不再呼叫 decodeAudioData 解析整個 MOV/MP4。按下自動對齊時，優先用下述快速音軌解碼；不支援或失敗時，以同一個 AudioContext 和每部影片唯一的 MediaElementAudioSourceNode，將播放器解出的聲音交給 AudioWorklet 擷取為 16 kHz 單聲道。原始音檔不需上傳或轉檔。

使用播放器備援的影片須以原速播放，若兩部都使用備援，約需兩部片長總和，畫面顯示讀取進度和來源預覽；可取消，切至背景或停滯時中止。讀完整部音訊是為了搜尋可能的时间差；成功判定以明確的局部音樂片段為依據（自動模式選擇確認長度），不要求尾段相同。已完成擷取會暫存在記憶體，換秒數重試不重播；取消或失敗的半成品不當作成功快取。

擷取依音訊渲染時間與播放器媒體時間定位樣本，等待/恢復播放時重新建立時間對應。融合直接把選定播放器音軌送到錄製器，前端裁切與畫面使用同一播放器位置，較短音軌結束後保持靜音；重複比對與輸出會沿用音訊來源，避免重複連接錯誤。清除或換片時釋放來源連接，頁面結束時關閉音訊環境。

測試涵蓋 44.1/48 kHz 擷取、啟動時間差與停頓後仍找出 AAC 素材的 2.34 秒偏移、換秒數快取、取消、切至背景、靜音、音訊處理錯誤、重複輸出及正負裁切。測試環境的播放器生命週期為模擬，尚需使用者 iPhone Safari 真機驗證。

## 開頭靜音誤判修正

重現：已知相差 2.34 秒的 AAC 素材，分別將開頭 0.18／0.12 秒設為數位靜音，舊版本的 0 秒與 5 秒模式都誤判為 0.06 秒。原因是靜音切換的 log 能量跳變同時出現在六個頻帶，壓過真正音樂特徵。現在將數位靜音、跨越靜音邊界的 FFT 視窗，以及恢復有聲後 120 ms 的過渡視窗排除；時間索引保留，沒有裁掉或平移音訊。回歸測試驗證正負 2.34 秒、恰好 2 秒、無關聲音不因共同靜音邊界而成功，以及正式 Worker 的 0／5 秒設定。使用者實際影片未提供，因此尚未對該檔案做真機驗證。


## 快速音軌解碼與備援

對齊前以隔離 Worker 和 Mediabunny 從 MOV／MP4 讀取主要音軌，不轉碼影像，也不把整個影片交給 decodeAudioData。支援的音軌以 WebCodecs AudioDecoder 解码；PCM 音軌使用套件內建解碼。依 presentation timestamp（含 edit list 位移）轉為 16 kHz 單聲道，保留開頭空白與原始影片時間軸。

瀏覽器不支援、EncodingError／decoding failed、空白或不完整音訊、Worker 載入錯誤，均逐片切回第 13 版播放器擷取路徑；12 秒無進度或總計 45 秒會終止快速 Worker 再走備援。取消或切到背景則終止作業，不啟用備援，也不保留未完成 PCM。介面顯示「快速讀取」或「相容模式」，成功音訊沿用既有快取。快速路徑不新增上傳或伺服器轉檔。

驗證包含真實 MOV PCM 音軌、44.1／48 kHz、音軌延遲 edit list、混用快速與播放器、解碼錯誤／逾時／取消及正式打包 Worker。原生 AAC 解碼仍須在使用者實際 iPhone Safari 與影片上驗證；較舊 Safari 沒有 AudioDecoder 時自動備援。第 13 版還原標記：restore-2026-09-10-auto-match-recrop。


## 獨立雙影片試聽

匯入至少一部影片後，來源區提供兩個小型試聽畫面。A／B 各自播放、暫停及拖動位置；「同時播放」依試聽專用時間差與共同位置開始，兩邊聲音一起輸出；「全部暫停」也可取消尚未啟動的播放。正數跳過 A 開頭、負數跳過 B 開頭。

試聽建立自己的 video 元素、音訊快取與 AudioContext，只接收來源檔案／URL／片長，完全不讀寫編輯的時間差、對齊狀態、裁切範圍、排版或融合結果。換來源時重設試聽，切到背景或開始其他處理時暫停。

同時試聽先在專用快取讀取兩部音訊：快速音軌解碼不支援時，沿用播放器依序讀取的備援。準備期間顯示進度並可取消；成功後以兩個 AudioBufferSourceNode 在同一 AudioContext 時間啟動，依試聽時間差與共同位置指定 offset。小畫面靜音播放、依音訊時鐘校正位置；Safari 暫停或拒播其中一個小畫面，不會停止音訊或否決同時試聽。暫停／拖动個別影片只停止該路音訊；已準備的聲音可反覆試聽，不需再次讀取。原生聲音路徑在混音時歸零，避免重複出聲。實際 iPhone 聲音與介面仍需實機確認。
